    How it works

    Local log sanitization without the upload step

    SanitizeLog is designed for diagnostic data that may contain credentials, tokens or other values that should not be shared unnecessarily.

    01

    Select your file

    Choose a supported diagnostic or configuration file up to 500 MB, or paste text directly into the sanitizer.

    02

    Process locally

    A Web Worker processes the content in your browser while the interface reports byte-based progress in real time.

    03

    Review and download

    Review replacement statistics and download the sanitized result without changing your original input file.

    Supported formats

    Common diagnostic and configuration files

    The current interface accepts common text-based diagnostic and configuration formats.

    Current security baseline

    The current default profile detects bearer JWT patterns and generic password key-value assignments. Detection rules are profile based and can be expanded independently from the user interface.

    Privacy by design

    Keep diagnostic data in your browser

    SanitizeLog is designed around local processing. The sanitizer runs inside a browser Web Worker rather than requiring the original diagnostic file to be uploaded to a remote processing service.

    Frequently asked questions

    SanitizeLog FAQ

    What is SanitizeLog?

    SanitizeLog is a browser-based diagnostic log and configuration sanitizer. It detects supported sensitive values and replaces them with deterministic security tokens without requiring the original file to be uploaded to a server.

    Does SanitizeLog upload my log file?

    The sanitizer is designed to process the selected file locally in your browser using a Web Worker. The original file does not need to be uploaded to a remote processing server.

    Can I sanitize a 500 MB log file?

    Yes. The current application supports input files up to 500 MB. Large file processing uses browser Blob streaming and incremental decoding instead of calling file.text() on the entire input.

    How does the percentage progress work?

    Progress is based on bytes processed compared with the total input size. The sanitizer updates the percentage, progress bar and processed byte count while the Web Worker processes the file.

    What does the current security profile detect?

    The current default security baseline includes bearer JWT patterns and generic password key-value assignments. The ruleset can evolve independently as additional detection rules are added.

    Does sanitization modify my original file?

    No. The selected input is treated as the source content. The sanitizer generates a separate sanitized result that can be downloaded.
